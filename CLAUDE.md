# CLAUDE.md — FM27 Manager

Windows desktop app (Tauri 2 + React 19 + TypeScript) to manage a Football Manager 27 squad: players and attributes, role ratings, automatic best XI, drag-and-drop tactics. See README.md for the feature list.

The user is French: **answer in French**. The UI is in English only (French was removed in v0.25.0).

## Commands

The PATH in Claude Code sessions can be stale on this machine. Prefix commands with:
`$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')`

- `npx tsc -b`, `npx vitest run`, `npx oxlint`: run all three after every change (they must stay clean; one known warning in `src/store.tsx`).
- `npm run tauri dev`: hot-reload dev app (run in background). While it runs, front-end edits apply live: **don't rebuild after each change**.
- **Releases are built by GitHub Actions** (`.github/workflows/release.yml`) on every pushed `vX.Y.Z` tag: it runs tsc + vitest, builds the NSIS/MSI installers, signs the updater artifacts and publishes the release with `latest.json`. The release title is the tag message's first line, the notes are the rest (Markdown). Routine for a new version: bump the version (3 files + package-lock), commit, `git tag -a vX.Y.Z -F <message file>`, `git push origin main`, `git push origin vX.Y.Z`. Don't build locally.
- The installed app updates itself (tauri-plugin-updater): at startup it reads `https://github.com/Nattends/fm-manager/releases/latest/download/latest.json`, offers the update in a toast, installs it (passive NSIS) and relaunches. Settings › Updates has a manual check. The signing private key is `~/.tauri/fm27-manager.key` (no password), also stored in the repo secret `TAURI_SIGNING_PRIVATE_KEY`; the public key is in `tauri.conf.json` (`plugins.updater.pubkey`). Losing the private key breaks updates.
- Local build (only if needed, e.g. CI down): set `$env:TAURI_SIGNING_PRIVATE_KEY = Get-Content ~/.tauri/fm27-manager.key -Raw` first (createUpdaterArtifacts needs it), then:
  1. Stop the installed app (allowed without asking). The dev exe has the same process name: only kill the one under `%LOCALAPPDATA%\FM27 Manager`.
  2. `npx tauri build`
  3. `Start-Process "src-tauri\target\release\bundle\nsis\FM27 Manager_0.8.0_x64-setup.exe" -ArgumentList '/S' -Wait`
  4. Check the exe's LastWriteTime.
  Do this when dev mode isn't running, or when the user asks for it.
- Never take screenshots or steal focus: the user is often playing on the same machine.

## Architecture

- `src/domain/`: **pure logic, no React or Tauri**, covered by Vitest (`*.test.ts`). Put new calculation logic here, with tests.
  - `rating.ts`: weighted attribute average (1-20; attributes outside the role share `OTHER_ATTRIBUTES_SHARE` = 15 % of the weight) → `RATING_CURVE` (score /100, calibrated on a full FM27 database: best player ≈ 97, top 1000 ≈ 74) × `FAMILIARITY_CURVE` factor (never played ×0.5). Stars (CA/PA) are **not** used in ratings.
  - `lineup.ts`: `computeLineup` (locked players first, then Hungarian assignment maximising the overall score = mean of the in-possession and out-of-possession ratings; backups are exclusive: `BACKUPS_PER_SLOT` rounds of Hungarian assignment over the bench, so a substitute backs up one slot only), `placePlayer` / `benchPlayer` / `moveSlot`, `summarizeLineup`, `lineOf`. The Tactics page calls it with `autoFill = false`: only placed (locked) players are starters; `fillEmptySlots` / `bestEleven` / `clearEleven` write the auto choice into the locks.
  - Phases: a `TacticSlot`'s `row/col/roleId` are the **in-possession** shape and `oop` the **out-of-possession** shape (same player). UI edits go through `phaseSlots` (view of a phase) → existing helpers (`moveSlot`…) → `mergePhase` / `patchShape`. `normalizeTacticSlots` fills `oop` for older tactics and drops the FM24 `duty` (no duties in FM26/27).
  - The Tactics page never shows player photos (cards: rating before the name, age · flag · familiarity, next backup).
  - `pitch.ts`: grid of 6 rows (0 = ST … 5 = GK) × FM's 5 lanes: 5 cells in the D, DM, M and AM rows, 3 in the ST row (central lanes). A card's position comes from its cell (`positionAt`); cards 19 % wide fit side by side. Tactics saved with the former 9-column half-space grid (`tactics.grid = 9`, backups v3) go through `narrowHalfSpaceGrid` (lineup.ts) / `narrowCells`; grid 5 rows and backups v1, v2, v4 are already on lanes.
  - The Tactics page pitch is always vertical (own goal at the bottom, no landscape view) and takes the full height of its area (width up to `PITCH_RATIO`).
  - `defaultRoles.ts`: `DEFAULT_ROLES` = `FM_ROLES` only (the notebook profiles were removed) (`fmRoles.ts`, generated from the sortitoutsi page « FM26: Important Attributes for Every Role »: 68 FM26/27 roles with `phase` ip/oop, weights 5 = line physical attributes, 3 = key, 1 = preferred, ids prefixed `fm-`). Obsolete roles (FM24, notebook ids) are stripped from a stored custom list at load (`cleanStoredRoles`). `DEFAULT_ROLE_BY_POSITION` / `DEFAULT_OOP_ROLE_BY_POSITION` (`defaultRoleFor(position, phase)`) pick the default in / out of possession role per position.
  - `nationalities.ts`: nationality = flag-icons code (`fr`, `gb-eng`…), names from `Intl.DisplayNames`; `nationCode` also resolves old free-text values (« Brésil »). Photo search compares the English name.
  - `clubMatch.ts`: picks the Transfermarkt club for a name (exact name, then all words, skipping reserve/youth teams unless asked).
  - `photoMatch.ts`: picks the Transfermarkt candidate (name tokens, age gap −1…+10, nationality preferred; French country names mapped via `Intl.DisplayNames`).
  - `fmSave.ts`: converts the raw players of an FM27 save (`SavePlayer`) into app players: `SAVE_VALUES` (order of the 54 raw values, 1-100 shown as `round(v / 5)`), `SAVE_POSITIONS`, `FM_NATIONS` (internal nation id → flag code), `planSaveImport` (updates keep name, stars, wage, value, status, notes, photo).
  - `scouting.ts`: decodes the scouting database (every player of the save, binary written by `scouting_snapshot` in `fm_save.rs`, stored as `scouting.bin` in the app data dir by `fm_scout_refresh`), `rateScout` (same rating as the squad, via `rateWith`, on raw values), `searchScouts` (filters, sort, limit). The Scouting page keeps the decoded database in memory (`loadScouting` in `src/data/fmSave.ts`).
  - `moneyball.ts` (Moneyball tab, `MoneyballPage.tsx`): ranks the scouting database by 4 criteria in rating points, summed with user weights (`DEFAULT_WEIGHTS`; every Moneyball coefficient is a `MoneyballParams` field, every rating coefficient a `RatingParams` field (`setRatingParams`, caches keyed on `ratingParamsVersion()`), both editable in Settings › Rating method (`ScoringSettings.tsx`, stores in `lib/scoringParams.ts`, localStorage `moneyball.params` / `rating.params`); the page evaluates once (`evaluateMoneyball`, slow) then ranks (`rankMoneyball`: weights + sort, fast)): **gain** = rise of the best XI starter at the best slot of the chosen tactic + `DEPTH_SHARE` of the backup's rise (`teamSlots` / `slotGain`); **surplus** = best rating − market curve (median rating vs log10 transfer value, isotonic, per line × age band, learnt by `buildModel`); **output** (« Rendement », `buildOutput` / `outputPoints`) = season production per 90 (`statValue`: xG, xA, goals, shots on target, dribbles, tackles won, passes, pass %, aerial duels won / %, cross %, save %, goals conceded (`OUTPUT_LOWER_BETTER`: counted negatively), average rating; extended stats via `seasonStat`, null on FMS5 databases) as a weighted z-score index per `OutputGroup` (gk, cb, fb, dm, mid, att; weights `OUTPUT_WEIGHTS`), minus the index expected from the player's rating and club level (2-variable regression per group), in residual standard deviations × `OUTPUT_POINTS_PER_SD`, shrunk by minutes / (minutes + 900), capped ±12, null below 450 minutes (dividing by the slope saturated: production barely follows attributes). Goal: spot great attributes / poor output and the reverse; **contract** = surplus gained by the reduced fee (`feeFactor`). Save data gaps it works around: value 0 € = unknown (`knownValue`), contract end and wage unknown for ~half the players (cost = value only; unknown wage passes the wage filter), « no club » ≠ free agent (some clubs aren't decoded). The squad's own club is excluded via `squadClubIndex`. « Realistic » mode (on by default, `reachOf` / `withinReach`): no reputation or budget in the save, so club level (`clubLevels` = mean best rating of a club's 16 best players) ≤ own + `REACH_CLUB_MARGIN`, player rating ≤ own club level + `REACH_LEVEL_MARGIN`, fee ≤ mean value of the squad's 11 most valuable players, wage ≤ top squad wage × `REACH_WAGE_FACTOR`; unknown amounts pass.
  - `replacements.ts` (« Replacements » tab of the player sheet, `ReplacementsTab.tsx`): teammates (`squadReplacements`, loaned-out excluded) and scouting players (`scoutReplacements`, squad excluded by name + nationality, max age / hide loaned / limit) whose rating on a target is ≥ the player's, compared rounded as displayed. Target = a slot of one of the club's tactics (`tacticTargets`: in- and out-of-possession role + position, score = their mean like `computeLineup`; `defaultTarget` = the slot the player is placed on, else his best slot) or a single role (« Any role »). Clicking a row opens `CompareDialog` with `second` and `role` preset.
  - `clubCompare.ts` (« Clubs » tab, `ClubComparePage.tsx`, e.g. before a job interview): two clubs of the scouting database lined up in one of the user's tactics (`clubReport`: players with `club` = the club, loaned-in ones made available; automatic best XI via `computeLineup` on `clearEleven` slots, both phases; depth = mean overall of the first backups; level = mean best rating of the 16 best like `clubLevels`; age, known value total, top known wage). Club A defaults to `squadClubIndex`; the club picker lists clubs by level (`searchClubs`).
  - `seasonStats.ts`: season stats of a scouting player (`SEASON_STATS`, `STAT_DEFS`: totals, per 90, percentages with a minimum of shots/passes/tackles, goals − xG; detailed stats null in leagues without tracking), `seasonStat`, `formatStat`. Scouting table columns (stats hidden by default except minutes, goals, assists), sortable (`ScoutSort` includes `SeasonStat`), `minMinutes` filter. `statPercentiles.ts`: percentile of a rate stat among players of the same `OutputGroup` (`primaryPosition`) with ≥ `PERCENTILE_MIN_MINUTES`, cached per database; shown in the Scouting detail panel (`components/ScoutStats.tsx`, `PlayerDetail extra`).
  - `search.ts`: `matchesSearch` (every word, accent/case/punctuation-insensitive via `normalizeText`) and `commandFilter` (pass to cmdk `<Command filter>`). Use them for every search box.
  - Each app club remembers its save (`src/lib/saveLink.ts`, localStorage). `src/lib/refreshFromSave.ts` (Settings › Refresh data) re-reads it: squad import without preview, then scouting database.
- `src-tauri/src/fm_save.rs`: reads a `.fm` save (zstd frames, ~400 MB decompressed, ~2 s): name tables, player blocks (15 position bytes + 54 values, then the identity record, usually 1-3 KB later but over 4 KB for some players: `next_marker` searches 4 KB, then up to 16 KB as long as no other block comes first), contracts, clubs and their teams, header (manager, managed club, game date). The last save read is cached (key: path + size + modification time). Commands `fm_save_scan` / `fm_save_players`; ignored test `reads_real_save` runs on a real file (`FM_SAVE=… cargo test --release -- --ignored`). Wage = u32 17 bytes into the contract record, weekly in GBP (`EUR_PER_GBP` in `fmSave.ts`). Transfer value = u32 in GBP right after the 54 values (block + 69); `FFFFFFFF` and exactly 300 000 000 (placeholder of ~2 000 players without a computed value) mean unknown; the game shows a range around it. The scouting database stores it since format `FMS3` (`FMS2` still decodes, without values). Season stats (`season_stats`): player stats records follow each other (ids are *not* always increasing: only the distance ≤ 40 000 bytes matters); each ends with a season summary (8-byte entries `02 [sum of ratings×10 u16] ? [matches] …`, one per competition), `10`, 16 slots of 3 bytes `[rating×10][competition][season]` (last ratings; season byte 06 = 2026, 07 = 2027, accepted 4..=12), `01`, then the next record's id; player X's block is the first one after the marker `01 [X+1]`. Average = Σsum / Σmatches / 10 (game value within ±0.03, ratings being rounded to 0.1). Inside a record, `01 07` slots of ~155 bytes (≥ 150 apart, `read_slot`): one per competition then the total, plus others (national team, past season…) before, after or in between; the total is the first slot equal to the sum of a subset of the previous ones on (rating sum, minutes, starts, subs) (`season_total`; a lone slot is its own total). Slot offsets after `01 07`: u16 rating sum×10 @0, minutes @2, u8 starts @4, subs @5, rated @6, goals @7, assists @8, player of the match @12; u16 passes @25, passes completed @27, tackles @29, tackles won @31, dribbles @37, shots @43, on target @45, xG×100 @89, xA×100 @91 (checked against an in-game stats screen of 21 players). Identified without an in-game reference (per-position profile + whole-database balances, see the `SLOT_LEN` comment): u16 fouls @39, fouled @41 (sums equal), aerial duels @33 / won @35, offsides @47, crosses @129 / completed @131; goalkeepers u8 conceded @9, saves @61. Not identified yet (several candidate fields, needs an in-game screen with these columns): progressive passes, interceptions, key passes, clearances, blocks, clean sheets. Research data: dump `totals.bin` (id + 155-byte total slot) and player positions, then profile each offset per position group per 90 and check balances. Leagues without tracking only have goals / ratings. Stored as `FMS6` (rating + minutes + 5 u8 + 9 u16 + 7 u16 + 2 u8 of `SeasonStats`; `FMS5` = without the extended stats, `SeasonStats.extended` false; `FMS4` = rating only) in the scouting database and in `players.avg_rating` / `rated_matches` (migration 008). League and CA/PA stars are not decoded (league: not stored on the club record).
- Youth tab (`YouthPage.tsx`, command `fm_save_youth` → `club_youth` in `fm_save.rs`): teams of the club after the first (`teams[1..]`, labelled U19, U18…) plus **affiliated teams** (B, C…) = teams of other clubs where ≥ 5 players have the club's first team as first contract and that team as last contract (a loan keeps the first team last). Team names/types are not decoded in the save, so labels are by rank. Read-only, not imported into the squad; reads the save linked to the active club.
- `src/data/`: the `DataSource` interface is implemented by `ManualSource` (SQLite). A future `MemorySource` (reading FM27 memory) must implement the same interface. `transfermarkt.ts` fetches through the Rust command `transfermarkt_get` (host whitelist in `src-tauri/src/lib.rs`).
- `src/store.tsx`: global state, plus the photo search queue (one player at a time, 1.5 s pause, cache table `photo_cache` keyed by name + nationality) and the club logo queue (`club_logo_cache`, keyed by normalised club name).
  - **Clubs**: one managed club = one FM save. `players` and `tactics` exposed by the store are those of the **active club** (`activeClub`, remembered in localStorage); the source returns all clubs. Roles are shared. `App` remounts the page when the club changes.
  - Loaned-out players (`onLoan`, `club` = host club) are out of the squad: separate tab in Squad, filtered out of Tactics, never picked by `computeLineup`.
- `src/i18n/`: `en.ts` holds every UI string (the `Messages` type); `useI18n()` always returns English (`lang` = `'en'`). No hard-coded text in components.
- Navigation (`App.tsx`, ids in `domain/navigation.ts`): 4 header tabs (Squad, Tactics, Recruitment, Settings), each with a sub-tab bar (`NAV`). `PAGES` maps each sub-tab to its page (`SquadPage view`, `SettingsPage section`…). localStorage `app.page` = `section/sub` (old 8-tab ids migrated by `parsePage`), `app.sub.<section>` = last sub-tab of each tab.
- `src/components/ui/`: generated by shadcn (radix-nova style), excluded from lint. Don't hand-edit them except for real fixes (e.g. `sonner.tsx` uses a fixed dark theme).
  - Tables (Squad, Scouting): click a header to sort (Scouting: second click reverses; `ScoutFilters.desc`, unknown values always last), columns can be hidden from the « Columns » menu and reordered by dragging headers (`ColumnDnd` / `ReorderableTh` in `ReorderableColumns.tsx`, pure logic in `domain/columnLayout.ts`, persisted in localStorage by `lib/columnPrefs.ts`: `squad.columns` + `squad.columnOrder`, `scouting.columns`).
  - Business components live in `src/components/`: `ui.tsx` (`PlayerAvatar`, `RatingBadge`, `Stars`), `chips.tsx`, `layout.tsx` (`PageHeader`, `Panel`, `StatTile`…), `RolePicker.tsx`, `PositionPitch.tsx`.
  - `styles.ts` is the single source of colours (scores, attributes, familiarity, statuses, pitch lines).
- `src-tauri/`: plugins (sql, dialog, fs), SQL migrations (`migrations/00N_*.sql`, declared in `lib.rs`; add new ones, never edit existing ones), window permissions in `capabilities/default.json`.

## Conventions and pitfalls

- **Never use `window.confirm` / `alert`**: the Tauri dialog plugin replaces them with async versions (a Promise is always "true"). Use `askConfirm()` from `src/lib/confirm.ts`.
- sqlx stores a checksum of each migration's exact bytes: a migration applied from a CRLF working copy fails on a CI build ("migration N was previously applied but has been modified"). `lib.rs` normalises the SQL to LF; keep migration files in LF.
- Radix `Select` doesn't accept `value=""`: use a sentinel (`'all'`, `'new'`).
- dnd-kit: drop zones must stay mounted. The "Squad" tab of Tactics uses `forceMount`.
- Colours: dark theme only (slate surfaces, emerald accent); variables live in `src/index.css`. Use `cn()` (from `@/lib/utils`) for classes.
- `@/` alias → `src/`.
- Window: freely resizable and maximisable, min 760×560 (`tauri.conf.json`), opens at 1500×950; position, size and maximised state are saved on every move/resize and restored at startup if still on a screen (`lib/windowMode.ts` `restoreWindow` / `trackWindow`, pure checks in `domain/windowGeometry.ts`, localStorage `window.geometry`). No manual window mode: **the layout must work from 760 px wide (half of a vertical 1080p screen) to 2560+**, using Tailwind breakpoints (`lg` = 1024, `xl` = 1280). Patterns: list + player sheet → `DetailPane` (`components/layout.tsx`: shown only while a player is selected, with a close button; side column ≥ lg, overlay below); Tactics: panel beside the pitch, below it in a portrait window, over it (toggle) in a narrow landscape window (< 1200) or big view; toolbars wrap (`PageHeader` is `flex-wrap`), button labels hide below 2xl (`TOOL_LABEL`).
- Code comments are written in French. Match the style of the surrounding code.
- Demo players are tagged `[demo]` at the start of their notes (`DEMO_MARKER`). `randomSquad.ts` (`randomTeam(seed)`) builds random test teams: a real club from `RANDOM_CLUBS`, a pool of real players by profile/side, invented names per nationality.
